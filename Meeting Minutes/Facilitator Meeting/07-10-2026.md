### Topic 2: Reflections and learnings (last facilitator meeting)
  - **Nyx:** Collaboration matters, and a team needs one strong, experienced leader to break down requirements and assign tasks. Rotating between three team leaders caused friction at each handover.
  - **Li:** Communication between members matters as much as individual coding skill. People need to understand each other's work (e.g. data collection must know what the website needs). Waiting for responses was the main issue.
  - **Thushamini:** A project needs clear communication, shared responsibility, starting early, keeping each other informed and testing how individual contributions fit together. The team supported each other well, with occasional communication gaps because everyone was busy.
  - **Leon:** State your strengths early. He was strong in front end, but that role was already taken, so he learned MySQL backend integration on the job. The team held each other accountable and reminded each other about the weekly objectives.
  - **Sunjol:** Collaboration was good given everyone's part-time schedules. Scope creep and client availability can derail a project: the client was unavailable from about week 5 to week 8/9, so the classification architecture couldn't be finalised. He built prototypes for three possible architectures (API LLM, self-hosted LLM, no LLM) and shared a schema with the backend team. Lesson: discuss such dependencies early and plan for unavailability.
  - **Facilitator feedback:**
    - Imperfect teamwork is normal; this unit is a low-risk preview of real-world projects.
    - Confirm your understanding early by saying "This is what I'm hearing from you…", so the other person can correct it before work starts.
    - In the real world there is never more than one team leader. The rotation is only so several students experience the role.
    - Identify early who can and cannot lead, and have the courage to say so. "A good project is a completed project," delivered on time.

### Topic 3: Project walkthrough for the facilitator
  - Sunjol described the system: a scraper collects job postings in the target industry, a classification pipeline extracts skills and normalises job titles (e.g. "SDE 1" ≈ "Associate Software Engineer"), and the website works as a job portal for students.
  - Li demoed the website. It lists the collected jobs (4,000+ clean records), links through to the original postings so users can apply, shows postings translated into English, and displays the extracted skills.
  - Weekly data snapshots are uploaded to GitHub as a separate deliverable for the client (Adrian). One pull request is still pending.
  - Nyx noted that the site currently works as a job explorer rather than an analysis view: the analysis is done but not shown on the front end.
